# MoeReview 沉浸式学习工作台设计

## 1. 背景与目标

MoeReview 面向需要在有限时间内完成复习、练习和巩固的大学生。前端的核心任务不是展示一个 AI 聊天窗口，而是让用户在同一学习空间中完成阅读、做题、追问、回顾和沉淀笔记。

本轮只改前端，不修改 MCP Server、WebSocket 协议或持久化后端。

目标：

- 桌面端优先，提供宽敞、稳定、低干扰的学习画布。
- 消除遮挡、抽屉越界、布局跳动和无效按钮等体验问题。
- 让网页成为初始化后的主要交互入口，Agent 退到幕后。
- 提供分页专注与连续回顾两种互补阅读方式。
- 将即时问答变成贴近原文的上下文工具，而不是独立聊天应用。
- 用结构化教学组件提升重点识别、理解和主动回忆效率。

非目标：

- 不重构后端协议、MCP 工具或会话数据模型。
- 不开放任意可执行 HTML。
- 不用大面积毛玻璃、装饰动画或卡片堆制造视觉效果。
- 不在第一阶段实现协同编辑、云端笔记同步或新的模型服务。

## 2. 设计原则

### 2.1 大画布，受控阅读宽度

学习画布占满顶栏以下的可用空间，不放进居中的大卡片。普通正文保持约 760-860px 的舒适行宽；代码、公式推导、对照、流程和图解可扩展到 1000-1200px。

### 2.2 操作跟随内容

常用操作出现在选区、页面结尾或当前回答附近。用户不需要频繁把鼠标移动到屏幕四角，也不需要离开网页回到 Agent 对话。

### 2.3 稳定优先于炫技

所有固定或悬浮控件都预留真实布局空间。动画只使用 transform 和 opacity；正文换行、滚动锚点和组件尺寸不得因悬停、聚焦或流式输出发生无意义变化。

### 2.4 语义决定视觉

定义、对照、例题、推导、易错点和主动回忆使用不同的教学结构，但共享统一的色彩、间距、字体和响应式规则。视觉差异用于解释内容，不用于装饰。

## 3. 整体布局

桌面端使用明确的应用布局轨道：

```text
┌──────┬──────────────────────────────────────────┬──────────────┐
│ 工具 │ 顶栏：会话 / 状态             计时 / 主题 │ 上下文侧页    │
│ 轨道 │──────────────────────────────────────────│ 即时回答      │
│      │ 页边脉络   大尺寸学习画布                 │ 引用与追问    │
│      │            正文 / 宽幅教学组件             │ 固定笔记      │
│      │                                          │ 按需出现      │
│      │            页面结尾与翻页反馈              │              │
│      │              紧凑指令坞                   │              │
└──────┴──────────────────────────────────────────┴──────────────┘
```

- 左侧工具轨正常宽度约 56px，包含学习概览、错题、收藏和笔记。
- 专注模式将工具轨收成 8-12px 的边缘触发区；正文排版宽度保持稳定。
- 顶栏占有独立布局高度，视觉上保持轻量，不覆盖正文。
- 视口宽度不小于 1360px 时，上下文侧页使用 400px 独立轨道。1100-1359px 时使用 340px 独立轨道，并保证正文核心阅读列不小于 680px。低于 1100px 时改为底部工作表，不覆盖正文阅读列。
- 指令坞与正文中心对齐，默认高度约 52px，输入时向上增长，最大约 160px。
- 正文底部预留指令坞与安全区高度，最后一段内容和操作按钮始终可见。
- 全局层级使用固定 token，禁止组件自行创造任意 z-index。

移动端降级为单列布局。上下文侧页变为底部工作表，必须使用 fixed 定位到视口、安全区内边距和可见关闭按钮。底部导航与工作表不能同时占用同一操作层。

## 4. 标志性体验：页边学习脉络

大画布左侧设置一条随学习过程生长的页边脉络。它不是装饰时间线，而是当前学习状态和历史行为的空间索引。

节点类型：

- 当前知识页
- 已提问位置
- 易错点
- 已固定笔记
- 练习与结果页
- 下一学习页

功能：

- 显示当前页与整体进度。
- 点击节点直接跳转，并恢复对应页面的滚动位置。
- 在连续回顾模式中标示页面边界。
- 承载二段式越界翻页的蓄力反馈。
- 从固定笔记返回原始页面和引用段落。

默认只显示细线与必要节点。鼠标靠近或键盘聚焦时才展开页码、标题和操作，避免持续抢占注意力。

## 5. 阅读与翻页模型

### 5.1 分页专注模式

默认一次只显示一个学习页。页内自然滚动，页面切换时保留每页独立滚动位置。

在页面底部继续滚动时：

1. 首次到达底部仅显示下一页标题和继续提示。
2. 停留 400ms 后，再次产生明确滚动输入才触发翻页。
3. 反向滚动可以取消蓄力状态。
4. 输入框、代码编辑器和内部滚动区域聚焦时禁用越界翻页。
5. 顶部越界返回上一页默认关闭，避免误退。

键盘支持：

- Space 向下阅读，到底后进入下一页。
- Shift+Space 向上阅读。
- J/K 在非输入状态下切换下一页和上一页。

### 5.2 连续回顾模式

所有学习页按时间线连续展示，并保留明确页面边界、类型、结果和笔记标记。该模式不启用越界翻页。两种模式切换时必须保持当前学习页和可见内容锚点。

## 6. 学习内容与语义画布

Markdown 仍是主要内容协议。使用成熟的 Markdown AST 扩展实现结构化教学指令，替换不断增长的正则预处理逻辑。

第一组语义组件：

- concept：核心概念和必要条件
- compare：双栏或多项对照，窄屏自动纵向排列
- steps：过程、算法和推导
- example：例题与分步解析
- checkpoint：主动回忆问题
- mistake：易错点与错误原因
- memory：压缩记忆和口诀
- diagram：流程或关系图
- source：原始材料引用

普通内容不使用嵌套卡片。组件主要通过版式、缩进、边线、局部底色和宽度变化形成层级。

本轮同时接入经过清洗的有限 HTML 兼容能力。HTML 解析必须使用严格的 sanitize schema，只允许 mark、kbd、sub、sup、details、summary 等有限标签；禁止 script、内联事件、任意 style、危险 iframe、绝对定位和未经控制的 class。复杂布局必须通过语义组件实现。

## 7. 指令坞

底部组件定位为学习指令坞，而不是聊天记录框。

状态：

- 静止：约 52px 高的轻量胶囊，仅显示输入提示和发送操作。
- 聚焦：保持外部宽度稳定，显示引用标签与必要模式信息。
- 多行：根据内容向上增长，最大约 160px，之后内部滚动。
- 处理中：发送按钮变为明确进度状态，输入保持可见但避免重复提交。
- 专注：允许收为窄条，通过快捷键或点击恢复。

快捷动作不长期悬浮在输入框上方。它们只在选中内容或到达页面结尾时出现。

## 8. 上下文即时问答

### 8.1 呈现方式

短回答先显示为选区附近的答案透镜，适合一至三段解释。较长回答、代码、公式或连续追问转入右侧上下文侧页。

上下文侧页使用连续文档排版，不使用左右聊天气泡。顶部显示简短引用与问题，正文显示回答，底部保留紧凑追问输入。用户可执行：

- 深入解释
- 举例
- 基于当前内容出题
- 固定为学习笔记
- 新话题

关闭回答不会改变正文滚动位置。Esc 收起侧页，Ctrl/Cmd+J 恢复最近回答。

### 8.2 引用与笔记

选中正文后显示就地工具条：复制、解释、举例、出题、固定笔记。引用以可移除标签进入指令坞或即时问答。

即时回答默认是临时内容。只有用户主动固定时才保存为学习笔记，并记录：

- 引用原文
- 用户问题
- 最终回答
- 来源学习页和段落锚点
- 创建时间

第一阶段不替换浏览器原生右键菜单。选区工具条已覆盖高频操作，同时保留复制、检查和辅助功能等系统能力。

### 8.3 流式输出

保留现有 SSE 流式请求，但避免每个碎片立即触发完整渲染：

- 使用 animation frame 或短间隔批量提交文本更新。
- 预留回答区域最小高度。
- 仅当用户原本接近底部时自动跟随滚动。
- 用户向上阅读后停止抢夺滚动位置，并提供回到底部按钮。
- Markdown、代码和公式使用稳定容器，避免完成时从纯文本突然切换导致大范围重排。
- 支持取消当前请求和失败后重试。

### 8.4 记忆

默认开启当前学习会话的短期记忆：

- 每个学习会话独立保存，不串科目。
- 保留最近 8 轮、当前引用和固定笔记摘要。
- 超出预算后压缩旧上下文，不无限发送完整历史。
- 关闭并重新打开上下文侧页时不丢失当前会话。
- 新话题显式清空短期上下文，不删除已固定笔记。

该状态保存在前端 store 和本地持久层，不要求修改后端。

## 9. 视觉系统

主题首次跟随系统，并记住用户的手动选择。

语义色：

- Canvas：#F6F8FB / #121417
- Surface：#FFFFFF / #191C20
- Ink：#18202A / #F1F4F7
- Cobalt：#2F67D8 / #79A2FF，用于当前焦点和主要操作
- Teal：#137D76 / #53BEB4，用于掌握、完成和笔记
- Amber：#A66316 / #E4A64C，用于疑问、易错和提醒

字体角色：

- 章节标题使用宋体系中文字体，但不用于长正文。
- 正文与操作使用 PingFang SC、Microsoft YaHei 和 system-ui。
- 代码、数据、计时与页码使用 JetBrains Mono 或 IBM Plex Mono 回退栈。
- 字距保持 0；正文默认约 17-18px、1.7-1.8 行高。

材质与形状：

- 毛玻璃仅用于顶栏、临时工具条和指令坞。
- 正文、笔记和回答使用高对比实色表面。
- 普通控件约 6px 圆角，面板约 8px。
- 只有指令坞使用完整胶囊形。

## 10. 动效与稳定性

唯一重点动效是翻页：页边脉络推进，正文使用约 8px 位移和交叉淡入淡出表达阅读方向。其余微交互控制在 150-220ms。

约束：

- 不动画 width、height、top 或 left 来制造常规反馈。
- 输入框动态高度使用稳定外壳，不改变周围布局基线。
- 悬停、按压和选中状态不得改变组件边界。
- 所有动画可被用户输入打断。
- prefers-reduced-motion 下取消位移、连续进度和非必要过渡。

## 11. 前端组件边界

组件职责拆分：

- AppShell：应用轨道、响应式布局和层级管理
- LearningCanvas：分页/连续模式和滚动锚点
- LearningMargin：学习脉络、节点和导航
- SemanticMarkdown：Markdown AST 与语义教学组件
- CommandDock：输入、引用、发送和处理状态
- ContextLens：选区附近的短回答
- ContextPanel：长回答、追问、记忆和固定笔记
- SelectionActions：选区工具条
- LearningNotes：固定笔记及原文返回
- PageBoundaryNavigator：二段式越界翻页状态机

组件通过 store 中的明确 UI 状态协作，不通过 DOM 查询互相控制。后端消息仍经现有 sendEvent 和 store dispatch 进入。

## 12. 错误处理与恢复

- WebSocket 断开时保留当前内容，指令坞显示重连状态并禁止重复发送。
- 即时问答请求失败时在回答位置显示原因、重试和保留问题操作。
- 流式请求支持取消，取消后的部分回答可保留但不得进入记忆。
- 页面内容为空或协议异常时显示可恢复提示，不同时显示旧页面导航和无关空状态。
- 本地记忆或笔记解析失败时隔离损坏记录，不阻止应用启动。
- 所有异步按钮在处理中禁用并提供反馈。

## 13. 性能策略

- Pyodide、代码运行器、即时问答和重型图表按功能延迟加载。
- 页面级内容使用稳定 key，避免无关 store 更新重渲染整个 Markdown 树。
- 流式输出批量更新，避免每个 token 触发滚动和完整 Markdown 解析。
- 长连续回顾在页面数量较大时使用分段挂载或虚拟化。
- 图片声明尺寸或 aspect-ratio，非首屏资源延迟加载。
- 字体使用本地优先回退，不让中文在线字体阻塞首屏。

## 14. 可访问性

- 所有可点击目标桌面端至少 40px，触控场景至少 44px。
- 图标按钮提供可访问名称、focus-visible 状态和 tooltip。
- 对话框、侧页和底部工作表支持 Esc、焦点管理与返回触发点。
- 翻页、模式切换和流式完成通过 aria-live 提供克制提示。
- 颜色不是状态的唯一表达；节点同时使用形状、图标或文字。
- 键盘操作不会覆盖输入框、代码编辑器和浏览器系统快捷键。

## 15. 已知问题优先修复

实施第一阶段必须先修复：

- 移动端资料库遮罩出现但面板定位到视口外。
- 页面时间线存在内容时仍短暂显示无关空状态。
- 顶部和轨迹按钮触控尺寸不足。
- 输入框聚焦改变宽度导致布局移动。
- 文本域逐次写高度和流式自动滚动造成抖动。
- 固定控件遮挡正文底部或移动端安全区。
- 即时问答关闭后因卸载丢失当前记忆。

## 16. 验收标准

功能与布局：

- 1440px、1280px 桌面宽度下正文、上下文侧页和指令坞无重叠。
- 375px 手机和横屏下无水平滚动，所有抽屉和关闭按钮在视口内。
- 分页与连续模式切换保持当前页面和阅读位置。
- 越界翻页不会被触控板惯性单次误触。
- 指令坞从单行增长到最大高度时正文不跳动。
- 即时回答关闭再打开后仍保留当前会话上下文。
- 固定笔记可以回到来源页面和引用位置。

质量：

- build 和 lint 通过。
- 桌面与移动端关键流程使用浏览器自动化验证并截图复核。
- 控制台无运行错误和重复 key 警告。
- reduced motion 下功能完整。
- 键盘可完成翻页、打开问答、追问、关闭侧页和恢复焦点。
- 关键按钮均能触发预期状态，异步期间不可重复提交。

## 17. 实施顺序

1. 修复布局轨道、遮挡、移动端抽屉和触控尺寸。
2. 重构大画布、页边学习脉络和混合阅读模式。
3. 重做指令坞、选区引用和越界翻页。
4. 重做即时问答呈现、流式稳定性、会话记忆和固定笔记。
5. 引入语义 Markdown 组件与安全 HTML 子集。
6. 完成性能拆包、可访问性和跨尺寸视觉验收。
